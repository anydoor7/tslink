<h1 align="center">TSLink</h1>

<p align="center">

## Для чего это используют

- **Открывайте свою работу на телефоне.** Отчёт, созданный скриптом, сервер разработки, блокнот или API локальной модели доступны разрешённым устройствам по частному HTTPS-адресу.
- **Дайте одному человеку одно приложение на время.** Предоставьте партнёру фотобиблиотеку на неделю или коллеге предварительную версию на три дня. Доступ закончится автоматически; его можно прекратить и раньше.
- **Поручите доступ своему агенту.** Агент для программирования только что создал панель. Попросите открыть её вам и коллеге до пятницы. Он также может показать текущие публикации и отозвать доступ.

Приложения продолжают работать там же, где и раньше. TSLink управляет доступом к каждому и ведёт единый список: что открыто, кому и до какого момента.

## Быстрый старт

Нужны **Go 1.26.6+**, Git и учётная запись Tailscale с [включёнными MagicDNS и HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates). Готовые сборки ещё не опубликованы, поэтому установите из исходного кода:

```bash
git clone https://github.com/anydoor7/tslink.git
cd tslink && go install .
export PATH="$PATH:$(go env GOPATH)/bin"
```

Откройте доступ к странице:

```bash
mkdir -p tslink-demo && printf '<h1>Hello from TSLink</h1>\n' > tslink-demo/index.html
tslink share ./tslink-demo --name demo
tslink url demo --wait
```

При первом запуске TSLink выводит ссылку для входа и регистрации нового узла сервиса; ваша tailnet также может требовать одобрения устройства администратором. После регистрации откройте URL сервиса на разрешённом устройстве, вошедшем в вашу tailnet. Токен API не нужен.

Проверьте, что опубликовано, и удалите демонстрацию:

```bash
tslink status --urls
tslink remove demo
```

Когда серверная часть работает, можно также предоставить доступ к следующему:

| Объект | Команда |
|---|---|
| Локальное веб-приложение | `tslink share 3000` |
| Папка с файлами | `tslink share ./public --name files` |
| API локальной модели, например Ollama | `tslink add model --proxy localhost:11434` |
| База данных через частный TCP | `tslink add database --tcp localhost:5432` |
| Поддерживаемое приложение на своём сервере (Jellyfin, Immich, Home Assistant и ещё 13) | `tslink apps detect`, затем `tslink apps share jellyfin --yes` |

[Начало работы, платформы и фоновая служба →](getting-started.md)

## Выберите, кому открыть доступ

| Аудитория | Что нужно получателю | Проверяемая личность | Когда закончится |
|---|---|---|---|
| **Ваши устройства** | Вход в вашу tailnet | Подтверждённая учётная запись Tailscale | При удалении приложения |
| **Указанные люди** (частные HTTP/файлы) | Учётная запись Tailscale; внешние пользователи принимают приглашение для каждого приложения | Подтверждённая учётная запись Tailscale | В заданный срок (`--for 7d`) или по `tslink people remove` |
| **Любой, у кого есть URL** (Funnel) | Браузер | Любой; собственный вход приложения сохраняется | По умолчанию через 24 часа (`--funnel-ttl`) |
| **Гостевая ссылка для браузера** *(скоро)* | Браузер и необязательный PIN | Владелец ссылки | По её сроку или при отзыве |

```bash
tslink people add alice@example.com --apps photos --for 7d
tslink people list
tslink people remove alice@example.com
```

Для частных HTTP-сервисов и файлов сроки проверяются при каждом запросе. Отзыв блокирует новые запросы, но не возвращает скачанные данные и не закрывает уже принятые потоки и WebSocket-соединения. [Доступ для людей →](people.md) · [Границы доступа →](sharing.md)

## Для агентов

В TSLink есть MCP-сервер: агент может открывать доступ, выводить список, объяснять и удалять публикации так же, как вы. Добавьте его в локальный MCP-клиент:

```json
{
  "mcpServers": {
    "tslink": { "command": "tslink", "args": ["mcp"] }
  }
}
```

- **Точные результаты.** Автоматизация CLI поддерживает `--json` с `schema_version: 1` и стабильными кодами ошибок; `tslink mcp` использует JSON-RPC. `tslink manifest` описывает все команды и флаги. Агентам следует получать реальные URL через `tslink url <name> --wait`, а не составлять их самостоятельно.
- **Честное ожидание.** Новый узел, которому ещё нужен вход человека, сообщает `needs_login`, а не притворяется готовым.
- **Полномочия.** Локальный MCP работает с правами вашего пользователя. Удалённый MCP включается явно, доступен только в tailnet и разрешает указанные учётные записи или теги. Роли отдельных агентов, ограничения по приложениям и квитанции действий появятся *скоро*.

MCP в TSLink управляет самим TSLink. Если вы публикуете другой MCP-сервер через TSLink, ему по-прежнему нужны собственные разрешения на инструменты.
[Руководство для агентов →](agents.md) · [MCP-клиенты →](mcp-clients.md) · [Удалённый MCP →](remote-mcp.md) · [Автоматизация JSON →](json-automation.md)

## Когда выбрать другой инструмент

| Если вам нужно | Рассмотрите |
|---|---|
| Один локальный сервис на своих устройствах с уже работающим клиентом Tailscale | [`tailscale serve`](https://tailscale.com/docs/reference/tailscale-cli/serve) |
| Сервисы под управлением администратора со стабильными именами на нескольких хостах | [Tailscale Services](https://tailscale.com/docs/features/tailscale-services) |
| Публичный URL для webhook или демонстрации API без учётной записи Tailscale | [ngrok](https://ngrok.com/docs/start) или [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) |
| Устанавливать и запускать приложения на своём сервере, а также делиться ими | [Umbrel](https://umbrel.com) или [Coolify](https://coolify.io) |
| Платформа доступа с проверкой личности для всей организации | [Pangolin](https://github.com/fosrl/pangolin) или [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/) |

TSLink подходит, когда один человек запускает несколько приложений и хочет давать временный доступ каждому человеку к отдельным приложениям, с возможностью проверки самим владельцем и его агентом.

## Как это работает

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/service-map-dark.svg">
  <img src="assets/service-map-light.svg" alt="App, Docs, Database и Model — отдельные именованные узлы в одной tailnet, работающие под одним демоном TSLink на публикующем компьютере." width="720">
</picture>

Один фоновый демон запускает встроенный узел Tailscale для каждого приложения, предоставляя ему собственное имя и адрес. В частных HTTP-сервисах и файлах доступ контролируют `WhoIs` и разрешения людям либо правила `--allow`; сроки проверяются при каждом запросе. Необработанный TCP использует политику tailnet и аутентификацию серверной части. Tailscale обеспечивает транспорт tailnet, шифрование и сертификаты; TSLink — независимый проект. Все приложения используют один публикующий компьютер, и TSLink не изолирует их друг от друга. [Архитектура →](architecture.md)

## Состояние

Уже доступно: частные адреса приложений, доступ для людей со сроками и пакетами приглашений, публичный Funnel с истечением срока, проверки работоспособности и оповещения, рецепты для приложений на своём сервере, ограничения запросов по приложениям, перезапуск после сбоя в Windows, CLI и MCP. Также доступны: гостевые ссылки для браузера, гибкие сроки, журнал доступа, домашняя страница приложений, ограниченные роли агентов, подключение через QR и запросы доступа.

Единый список нескольких компьютеров запланирован. [План развития →](roadmap.md)
