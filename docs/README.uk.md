## Для чого це використовують

- **Відкривайте свою роботу на телефоні.** Звіт зі скрипту, сервер розробки, блокнот або API локальної моделі доступні дозволеним пристроям за приватною HTTPS-адресою.
- **Дайте одній людині один застосунок на певний час.** Відкрийте партнеру фотобібліотеку на тиждень або колезі попередню версію на три дні. Доступ завершиться автоматично; його можна припинити раніше.
- **Доручіть поширення агенту.** Ваш агент для програмування щойно створив панель. Попросіть відкрити її вам і колезі до п'ятниці. Він також може показати поточні спільні ресурси й відкликати доступ.

Застосунки працюють там само, де й раніше. TSLink керує доступом до кожного та веде один список: що відкрито, кому й до якого часу.

## Швидкий старт

Потрібні **Go 1.26.6+**, Git і обліковий запис Tailscale з [увімкненими MagicDNS та HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates). Готові збірки ще не опубліковано, тому встановіть із вихідного коду:

```bash
git clone https://github.com/anydoor7/tslink.git
cd tslink && go install .
export PATH="$PATH:$(go env GOPATH)/bin"
```

Відкрийте доступ до сторінки:

```bash
mkdir -p tslink-demo && printf '<h1>Hello from TSLink</h1>\n' > tslink-demo/index.html
tslink share ./tslink-demo --name demo
tslink url demo --wait
```

Першого разу TSLink показує посилання для входу й реєстрації нового вузла сервісу; ваша tailnet може також вимагати схвалення пристрою адміністратором. Після реєстрації відкрийте URL сервісу на дозволеному пристрої, що увійшов до вашої tailnet. Токен API не потрібен.

Перевірте спільні ресурси й видаліть демонстрацію:

```bash
tslink status --urls
tslink remove demo
```

Коли серверна частина працює, можна також відкрити доступ до такого:

| Ресурс | Команда |
|---|---|
| Локальний вебзастосунок | `tslink share 3000` |
| Папка з файлами | `tslink share ./public --name files` |
| API локальної моделі, наприклад Ollama | `tslink add model --proxy localhost:11434` |
| База даних через приватний TCP | `tslink add database --tcp localhost:5432` |
| Відомий застосунок на власному сервері (Jellyfin, Immich, Home Assistant і ще 13) | `tslink apps detect`, потім `tslink apps share jellyfin --yes` |

## Оберіть, кому надати доступ

| Аудиторія | Що потрібно одержувачу | Особа | Завершення доступу |
|---|---|---|---|
| **Ваші пристрої** | Вхід у вашу tailnet | Підтверджений обліковий запис Tailscale | Коли видалите застосунок |
| **Вказані люди** (приватні HTTP/файли) | Вхід у Tailscale; зовнішні користувачі приймають запрошення для кожного застосунку | Підтверджений обліковий запис Tailscale | У заданий термін (`--for 7d`) або через `tslink people remove` |
| **Будь-хто з URL** (Funnel) | Браузер | Будь-хто; власний вхід застосунку залишається чинним | Типово через 24 години (`--funnel-ttl`) |
| **Гостьове посилання для браузера** *(незабаром)* | Браузер і необов'язковий PIN | Власник посилання | За його терміном або після відкликання |

```bash
tslink people add alice@example.com --apps photos --for 7d
tslink people list
tslink people remove alice@example.com
```

Для приватних HTTP-сервісів і файлів терміни перевіряються під час кожного запиту. Відкликання блокує нові запити, але не повертає завантажені дані й не закриває вже прийняті потоки та WebSocket-з'єднання. [Доступ для людей →](people.md) · [Межі спільного доступу →](sharing.md)

## Для агентів

TSLink містить MCP-сервер, тож агент може відкривати доступ, показувати список, пояснювати й видаляти спільні ресурси так само, як ви. Додайте його до локального MCP-клієнта:

```json
{
  "mcpServers": {
    "tslink": { "command": "tslink", "args": ["mcp"] }
  }
}
```

- **Точні результати.** Автоматизація CLI підтримує `--json` із `schema_version: 1` і стабільними кодами помилок; `tslink mcp` використовує JSON-RPC. `tslink manifest` описує кожну команду й прапорець. Агентам слід отримувати справжні URL через `tslink url <name> --wait`, а не складати їх самостійно.
- **Чесне очікування.** Новий вузол, якому ще потрібен вхід людини, повідомляє `needs_login`, замість удавати готовність.
- **Повноваження.** Локальний MCP працює з правами вашого користувача. Віддалений MCP вмикається явно, доступний лише в tailnet і обмежений вказаними обліковими записами або тегами. Ролі окремих агентів, межі застосунків і квитанції дій з'являться *незабаром*.

MCP у TSLink керує самим TSLink. Якщо опублікуєте інший MCP-сервер через TSLink, йому все одно потрібні власні дозволи на інструменти.
[Посібник для агентів →](agents.md) · [MCP-клієнти →](mcp-clients.md) · [Віддалений MCP →](remote-mcp.md) · [Автоматизація JSON →](json-automation.md)

## Коли обрати інший інструмент

| Якщо потрібно | Розгляньте |
|---|---|
| Один локальний сервіс на власних пристроях із уже запущеним клієнтом Tailscale | [`tailscale serve`](https://tailscale.com/docs/reference/tailscale-cli/serve) |
| Керовані адміністратором сервіси зі сталими назвами на кількох хостах | [Tailscale Services](https://tailscale.com/docs/features/tailscale-services) |
| Публічний URL для webhook або демонстрації API без облікового запису Tailscale | [ngrok](https://ngrok.com/docs/start) або [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) |
| Встановлювати й запускати застосунки на власному сервері, а також ділитися ними | [Umbrel](https://umbrel.com) або [Coolify](https://coolify.io) |
| Платформа доступу на основі особи для всієї організації | [Pangolin](https://github.com/fosrl/pangolin) або [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/) |

TSLink підходить, коли одна людина запускає кілька застосунків і хоче надавати тимчасовий доступ окремо до кожного застосунку й людині, з можливістю перевірки власником та його агентом.

## Як це працює

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/service-map-dark.svg">
  <img src="assets/service-map-light.svg" alt="App, Docs, Database і Model — окремі іменовані вузли в одній tailnet, що працюють під одним демоном TSLink на комп'ютері, який публікує сервіси." width="720">
</picture>

Один фоновий демон запускає вбудований вузол Tailscale для кожного застосунку, надаючи йому власну назву й адресу. Для приватних HTTP-сервісів і файлів доступ контролюють `WhoIs` та дозволи людям або правила `--allow`; терміни перевіряються під час кожного запиту. Необроблений TCP використовує політику tailnet й автентифікацію серверної частини. Tailscale забезпечує транспорт tailnet, шифрування й сертифікати; TSLink — незалежний проєкт. Усі застосунки спільно використовують комп'ютер публікації, тому TSLink не ізолює їх один від одного. [Архітектура →](architecture.md)

## Стан

Уже доступні: приватні адреси застосунків, вказані люди з термінами й пакетами запрошень, публічний Funnel із терміном дії, перевірки працездатності й сповіщення, рецепти для застосунків на власному сервері, обмеження запитів за застосунками, перезапуск після збою в Windows, CLI та MCP. Також доступні: гостьові посилання для браузера, гнучкі терміни, журнал доступу, домашня сторінка застосунків, обмежені ролі агентів, підключення через QR і запити доступу.

Спільний список кількох комп'ютерів заплановано. [План розвитку →](roadmap.md)
