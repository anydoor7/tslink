## Πώς το χρησιμοποιούν οι χρήστες

- **Ανοίξτε τη δουλειά σας στο κινητό.** Μια αναφορά από το σενάριό σας, ένας διακομιστής ανάπτυξης, ένα σημειωματάριο ή το API ενός τοπικού μοντέλου, σε ιδιωτική διεύθυνση HTTPS προσβάσιμη από εξουσιοδοτημένες συσκευές.
- **Δώστε σε ένα άτομο μία εφαρμογή για λίγο.** Ο σύντροφός σας μπορεί να χρησιμοποιήσει τη βιβλιοθήκη φωτογραφιών για μια εβδομάδα ή ένας συνάδελφος να δοκιμάσει την προεπισκόπηση για τρεις ημέρες. Η πρόσβαση λήγει αυτόματα· μπορείτε επίσης να τη διακόψετε νωρίτερα.
- **Αφήστε τον πράκτορά σας να μοιραστεί την εφαρμογή.** Ο πράκτορας προγραμματισμού μόλις έφτιαξε έναν πίνακα ελέγχου. Ζητήστε να τον μοιραστεί μαζί σας και με τον συνεργάτη σας έως την Παρασκευή. Μπορεί επίσης να δείξει τι μοιράζεται τώρα και να ανακαλέσει μια κοινοποίηση.

Οι εφαρμογές συνεχίζουν να εκτελούνται εκεί που ήδη βρίσκονται. Το TSLink ελέγχει ποιος μπορεί να φτάσει σε καθεμία και κρατά μία λίστα με το τι μοιράζεται, με ποιον και έως πότε.

## Γρήγορη εκκίνηση

Χρειάζεστε **Go 1.26.6+**, Git και λογαριασμό Tailscale με [ενεργά MagicDNS και HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates). Δεν έχουν δημοσιευτεί ακόμη έτοιμα εκτελέσιμα, οπότε εγκαταστήστε από τον πηγαίο κώδικα:

```bash
git clone https://github.com/anydoor7/tslink.git
cd tslink && go install .
export PATH="$PATH:$(go env GOPATH)/bin"
```

Μοιραστείτε μια σελίδα:

```bash
mkdir -p tslink-demo && printf '<h1>Hello from TSLink</h1>\n' > tslink-demo/index.html
tslink share ./tslink-demo --name demo
tslink url demo --wait
```

Την πρώτη φορά, το TSLink εμφανίζει σύνδεσμο εισόδου για την εγγραφή του νέου κόμβου υπηρεσίας· το tailnet σας ίσως απαιτεί και έγκριση συσκευής από διαχειριστή. Μετά την εγγραφή, ανοίξτε το URL της υπηρεσίας σε επιτρεπόμενη συσκευή συνδεδεμένη στο tailnet σας. Δεν χρειάζεται διακριτικό API.

Ελέγξτε τις κοινοποιήσεις και αφαιρέστε τη δοκιμή:

```bash
tslink status --urls
tslink remove demo
```

Μπορείτε επίσης να μοιραστείτε τα παρακάτω όταν λειτουργεί το αντίστοιχο σύστημα υποστήριξης:

| Περιεχόμενο | Εντολή |
|---|---|
| Μια τοπική εφαρμογή ιστού | `tslink share 3000` |
| Ένας φάκελος αρχείων | `tslink share ./public --name files` |
| API τοπικού μοντέλου, όπως το Ollama | `tslink add model --proxy localhost:11434` |
| Βάση δεδομένων μέσω ιδιωτικού TCP | `tslink add database --tcp localhost:5432` |
| Γνωστή αυτοφιλοξενούμενη εφαρμογή (Jellyfin, Immich, Home Assistant και άλλες 13) | `tslink apps detect`, έπειτα `tslink apps share jellyfin --yes` |

## Επιλέξτε ποιος μπορεί να ανοίξει την εφαρμογή

| Κοινό | Τι χρειάζεται ο παραλήπτης | Ταυτότητα | Λήξη |
|---|---|---|---|
| **Οι δικές σας συσκευές** | Σύνδεση στο tailnet σας | Επαληθευμένη ταυτότητα Tailscale | Όταν αφαιρείτε την εφαρμογή |
| **Συγκεκριμένα άτομα** (ιδιωτικό HTTP/αρχεία) | Σύνδεση Tailscale· οι εξωτερικοί χρήστες αποδέχονται πρόσκληση ανά εφαρμογή | Επαληθευμένη ταυτότητα Tailscale | Στην προθεσμία σας (`--for 7d`) ή με `tslink people remove` |
| **Όποιος έχει το URL** (Funnel) | Ένας περιηγητής | Οποιοσδήποτε· ισχύει η είσοδος της ίδιας της εφαρμογής | Μετά από 24 ώρες από προεπιλογή (`--funnel-ttl`) |
| **Σύνδεσμος επισκέπτη σε περιηγητή** *(έρχεται)* | Περιηγητής και προαιρετικό PIN | Ο κάτοχος του συνδέσμου | Στη δική του προθεσμία ή με ανάκληση |

```bash
tslink people add alice@example.com --apps photos --for 7d
tslink people list
tslink people remove alice@example.com
```

Στις ιδιωτικές κοινοποιήσεις HTTP και αρχείων, οι προθεσμίες ελέγχονται σε κάθε αίτημα. Η ανάκληση σταματά νέα αιτήματα· δεν επαναφέρει κατεβασμένα δεδομένα ούτε κλείνει ήδη αποδεκτές ροές και συνδέσεις WebSocket. [Κοινοποίηση σε άτομα →](people.md) · [Όρια κοινοποίησης →](sharing.md)

## Για πράκτορες

Το TSLink περιλαμβάνει διακομιστή MCP ώστε ένας πράκτορας να μοιράζεται, να παραθέτει, να εξηγεί και να αφαιρεί κοινοποιήσεις όπως εσείς. Προσθέστε τον σε τοπικό πελάτη MCP:

```json
{
  "mcpServers": {
    "tslink": { "command": "tslink", "args": ["mcp"] }
  }
}
```

- **Ακριβή αποτελέσματα.** Ο αυτοματισμός CLI υποστηρίζει `--json` με `schema_version: 1` και σταθερούς κωδικούς σφάλματος· το `tslink mcp` χρησιμοποιεί JSON-RPC. Το `tslink manifest` περιγράφει κάθε εντολή και σημαία. Οι πράκτορες πρέπει να ανακτούν τα πραγματικά URL με `tslink url <name> --wait`, αντί να τα κατασκευάζουν.
- **Ειλικρινείς καταστάσεις αναμονής.** Νέος κόμβος που ακόμη χρειάζεται είσοδο από άνθρωπο αναφέρει `needs_login`, αντί να παρουσιάζεται έτοιμος.
- **Δικαιώματα.** Το τοπικό MCP εκτελείται με τα δικαιώματα του χρήστη σας. Το απομακρυσμένο MCP ενεργοποιείται προαιρετικά, είναι διαθέσιμο μόνο στο tailnet και περιορίζεται στις ταυτότητες ή ετικέτες που δηλώνετε. Ρόλοι ανά πράκτορα, όρια εφαρμογών και αποδείξεις ενεργειών *έρχονται*.

Το MCP του TSLink χειρίζεται το ίδιο το TSLink. Αν δημοσιεύσετε άλλον διακομιστή MCP μέσω TSLink, εξακολουθεί να χρειάζεται δικά του δικαιώματα εργαλείων.
[Οδηγός πρακτόρων →](agents.md) · [Πελάτες MCP →](mcp-clients.md) · [Απομακρυσμένο MCP →](remote-mcp.md) · [Αυτοματισμός JSON →](json-automation.md)

## Πότε να επιλέξετε άλλο εργαλείο

| Αν θέλετε | Εξετάστε |
|---|---|
| Μία τοπική υπηρεσία στις συσκευές σας, με τον πελάτη Tailscale που ήδη λειτουργεί | [`tailscale serve`](https://tailscale.com/docs/reference/tailscale-cli/serve) |
| Υπηρεσίες διαχειριστή με σταθερά ονόματα σε πολλούς υπολογιστές | [Tailscale Services](https://tailscale.com/docs/features/tailscale-services) |
| Δημόσιο URL για webhook ή επίδειξη API, χωρίς λογαριασμό Tailscale | [ngrok](https://ngrok.com/docs/start) ή [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) |
| Εγκατάσταση και εκτέλεση αυτοφιλοξενούμενων εφαρμογών πέρα από την κοινοποίησή τους | [Umbrel](https://umbrel.com) ή [Coolify](https://coolify.io) |
| Πλατφόρμα πρόσβασης βάσει ταυτότητας για όλο τον οργανισμό | [Pangolin](https://github.com/fosrl/pangolin) ή [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/) |

Το TSLink ταιριάζει όταν ένα άτομο εκτελεί πολλές εφαρμογές και θέλει χρονικά περιορισμένη πρόσβαση ανά εφαρμογή και άτομο, την οποία μπορούν να ελέγξουν τόσο το ίδιο όσο και ο πράκτοράς του.

## Πώς λειτουργεί

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/service-map-dark.svg">
  <img src="assets/service-map-light.svg" alt="Τα App, Docs, Database και Model είναι ξεχωριστοί επώνυμοι κόμβοι σε ένα tailnet, που εκτελούνται από έναν δαίμονα TSLink στον υπολογιστή δημοσίευσης." width="720">
</picture>

Ένας δαίμονας παρασκηνίου εκτελεί ενσωματωμένο κόμβο Tailscale για κάθε εφαρμογή, δίνοντάς της δικό της όνομα και διεύθυνση. Για ιδιωτικό HTTP και αρχεία, το `WhoIs` και οι άδειες ατόμων ή οι κανόνες `--allow` ελέγχουν την πρόσβαση· οι προθεσμίες ελέγχονται ανά αίτημα. Το ακατέργαστο TCP χρησιμοποιεί την πολιτική tailnet και την αυθεντικοποίηση του συστήματος υποστήριξης. Το Tailscale παρέχει μεταφορά tailnet, κρυπτογράφηση και πιστοποιητικά· το TSLink είναι ανεξάρτητο έργο. Οι εφαρμογές μοιράζονται τον υπολογιστή δημοσίευσης, άρα το TSLink δεν τις απομονώνει μεταξύ τους. [Αρχιτεκτονική →](architecture.md)

## Κατάσταση

Διαθέσιμα τώρα: ιδιωτικές διευθύνσεις ανά εφαρμογή, άτομα με προθεσμίες και πακέτα προσκλήσεων, δημόσιο Funnel με λήξη, έλεγχοι υγείας και ειδοποιήσεις, συνταγές αυτοφιλοξενούμενων εφαρμογών, όρια αιτημάτων ανά εφαρμογή, επανεκκίνηση μετά από κατάρρευση στα Windows, CLI και MCP. Διατίθενται επίσης: σύνδεσμοι επισκέπτη σε περιηγητή, ευέλικτες διάρκειες, αρχείο πρόσβασης, αρχική σελίδα εφαρμογών, περιορισμένοι ρόλοι πρακτόρων, ένταξη μέσω QR και αιτήματα πρόσβασης.

Η προβολή πολλών υπολογιστών σε μία λίστα έχει προγραμματιστεί. [Πλάνο ανάπτυξης →](roadmap.md)
